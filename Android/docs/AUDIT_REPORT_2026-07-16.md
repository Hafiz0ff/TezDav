# Аудит Android-приложения TezDav

Дата: 16 июля 2026 года

Путь проекта: `/Users/hafizov/Dav.TJ/Android`

Стек: Expo SDK 57, React Native 0.86, TypeScript, SQLite, Android API 26+

## Итог

Главная найденная проблема была не косметической: Android-каталог являлся отдельным незавершённым прототипом. В нём физически существовали только вкладки «Главная» и «Форма», упрощённая таблица активностей и экран деталей с текстовыми заглушками. Полная функциональность, которую ожидал пользователь, находилась только в Swift-проекте `TezDav` и никогда не была перенесена в Android.

В рамках аудита Android-прототип исправлен до стабильного локального приложения с пятью основными вкладками, расширенным хранилищем и реальными расчётами по импортированным данным. При этом Strava OAuth и импорт Strava в Android всё ещё отсутствуют. Это явно показано в приложении и вынесено в блокирующие задачи, а не замаскировано демонстрационными данными.

## Исправленные проблемы

### Критические

1. Удалён неверный стартовый экран с логином и паролем Supabase. Приложение сразу открывает локальный Dashboard.
2. Удалены Supabase-клиент, зависимости и `.env` с неиспользуемыми переменными. В release bundle нет маркеров Supabase или Strava Client Secret.
3. Восстановлена структура из пяти вкладок: «Главная», «Форма», «Рекорды», «Карта», «Профиль».
4. Release-вариант больше не подписывается debug-ключом. Production APK остаётся unsigned до подключения настоящего keystore/EAS credentials.
5. Исправлена автономная сборка: release APK содержит `assets/index.android.bundle`. Ошибка `Unable to load script` воспроизводилась только после установки debug APK без Metro; на эмулятор установлен release-вариант.

### Данные и расчёты

1. SQLite переведён на schema version 2 с миграцией без удаления старых активностей.
2. Добавлены поля высоты, пульса, мощности, каденса, скорости, полилинии, TRIMP, источника и статуса потоков.
3. Добавлены таблицы посекундных потоков, пользовательских настроек и состояния синхронизации.
4. Добавлены транзакционная замена потоков, внешние ключи, WAL и индексы.
5. CTL/ATL теперь считаются по календарным дням, суммируют несколько тренировок за день и заполняют дни без нагрузки.
6. Исправлены расчёты километровых сплитов, пульсовых зон и нормализованной мощности.
7. Реализованы лучшие отрезки из потока дистанции, оценка Daniels VO2max и прогноз Riegel.

### Интерфейс и сценарии

1. Dashboard показывает CTL, ATL, TSB, недельный объём по видам спорта и последние пять активностей.
2. «Форма» показывает PMC и переключение периода 30/90 дней/вся история.
3. «Рекорды» считает стандартные беговые дистанции только по реальным потокам и формирует отчёт за 30 дней.
4. «Карта» показывает список активностей с GPS-полилинией; детали отображают офлайн-контур трека.
5. «Профиль» локально сохраняет максимальный/покойный пульс, пороговый темп, недельную цель, FTP и основной спорт.
6. Детали активности используют реальные потоки для графиков, сплитов и зон и сравнивают тренировку с предыдущей того же типа.
7. Удалены выдуманная карта Сан-Франциско, mock-потоки, mock-сплиты и фиктивная готовность.
8. Health Connect не запрашивает разрешение автоматически; доступ запрашивается только после действия пользователя.

### Android и безопасность

1. Package ID: `com.hafizov.tezdav`; URL scheme: `tezdav`.
2. `allowBackup=false`, добавлены cloud/device-transfer backup rules.
3. В release-манифесте отсутствуют `SYSTEM_ALERT_WINDOW`, `READ_EXTERNAL_STORAGE` и `WRITE_EXTERNAL_STORAGE`.
4. Фактические разрешения APK: `INTERNET`, `VIBRATE`, `health.READ_STEPS` и внутреннее dynamic-receiver permission.
5. Добавлена обязательная конфигурация Health Connect для Android 14.
6. Минимальная версия Android поднята до API 26.

## Остаточные риски и незавершённые блоки

### Блокер: Strava Android

Android пока не выполняет OAuth, обновление токенов, пагинацию активностей, импорт потоков, rate-limit queue и фоновую синхронизацию. Поэтому новая локальная база остаётся пустой до появления импортера.

Официальный Strava token exchange требует одновременно `client_id` и `client_secret`, а Strava указывает, что secret нельзя раскрывать. Встраивание секрета в APK не является безопасным решением: APK доступен пользователю и может быть разобран. Для Android нужен минимальный token broker либо явно принятое владельцем небезопасное клиентское хранение секрета. Рекомендуется token broker.

Источник: https://developers.strava.com/docs/authentication/

### Прочее

1. Офлайн-превью показывает геометрию GPS-трека, но полноценная Google Maps подложка не подключена: в проекте нет Android Maps API key.
2. Почасовая фоновая задача не реализована.
3. Health Connect сейчас читает только шаги и не импортирует тренировки.
4. Большая реальная история Strava ещё не использовалась для нагрузочного теста SQLite/records screen.
5. Production signing credentials не настроены.
6. `npm audit --omit=dev`: 0 critical, 0 high, 11 moderate. Они находятся в Expo config tooling и `react-native-health-connect`. Предлагаемый forced fix понижает Expo до SDK 46 и Health Connect до 1.0.2, поэтому он несовместим и не применён.

## Вывод

Android-приложение теперь собирается, запускается автономно, не показывает стартовый логин и содержит рабочую локальную структуру основных экранов. Называть его полным Android-аналогом iOS пока нельзя: критический следующий этап — безопасная Strava-синхронизация и импорт реальной истории.
